# 动效提示词怎么写

归纳自 Opus 5.5 合集里写法评分最高的 172 条提示词（`pv` = 3），用自己的话总结，不含原文。要看原文时，用 `scripts/search.py --show <id>` 找到 `prompt_raw` 链接去读。

这份指南有两种用途：一是自己动手前把设计意图写成清晰的规格；二是用户要一段可以交给其他模型的提示词时，按这个结构写。

## 好提示词的共同点

1. **先定交付物和硬约束**：一个 HTML 文件、画布尺寸与帧率、时长、允许和禁止的库（如“只用 Canvas，不用库”“不用物理引擎”“不用外部图片”）。约束越具体，结果越稳。
2. **让每一帧是时间的函数**：要求用一个 `draw(t)` 之类的函数按时间绘制，便于截图、录屏、跳到任意时刻和逐帧自检。
3. **节奏先于画面**：先写节拍（如 120 BPM、几小节），再按拍写每个镜头，转场落在重拍上。“加内容而不是拉长时长”。
4. **逐镜头写衔接**：不只写每个画面是什么，还写它怎样变成下一个画面（“从上一场景长出来”“不硬切”“首尾帧可循环”）。
5. **数值化质感**：色值、字体分工、缓动曲线、点数、半径、速度、停留几拍，都给具体数。模糊词（“高级感”“炫酷”）几乎没有约束力。
6. **写禁用清单**：不要什么（不弹跳、不用渐变紫、不放占位数据、不出现虚构客户）往往比要什么更有效。
7. **用一个比喻统一全片**：如“一条不断的线描边、填色、流向下一个物体”，让材质和动作有同一个来源。
8. **交互写成可测行为**：按钮做什么、悬停显示什么、滑块联动什么、状态切换函数叫什么名（如 `setRole(颜色)`、`setBusy(true)`）。这样生成的代码能直接接进页面。
9. **要求自检**：先出静帧或分镜，再写动画；渲染后抽帧检查，按清单修正。
10. **内容要真实**：用产品真实信息和可核对的数字；涉及史实或科学时要求核对。

## 推荐结构

```
【交付】一个 HTML 文件 / Vue 组件；尺寸、帧率、时长；允许与禁止的技术
【场景与目的】给谁看、看完应留下什么印象
【视觉】底色与主色（色值）、字体分工、质感关键词、参考哪些案例的什么手法
【节奏与分镜】节拍；第 1 段……第 2 段……；每段如何衔接下一段
【交互与接口】鼠标、滚动、点击的行为；对外暴露的函数
【性能与降级】离屏暂停、减少动态效果、移动端减量、不支持时的静态结果
【禁用】不要什么
【自检】先出静帧确认，再写动画；完成后抽帧比对
```

灵枢的项目文档里有四段按这个思路写的场景提示词（知识星河、身份光门、AI 核心、15 秒宣传短片），可以当范本。
