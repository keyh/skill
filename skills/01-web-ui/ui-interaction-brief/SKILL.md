# 将界面意图写成可验收的交互说明

适用于“让 AI 做一个弹层/立体卡片，但描述不清楚”的任务。交付交互规格，不冒充已经写好或测试过组件。不限框架；不自动选择动画库或安装依赖。

根据两条已抽帧核对的收藏视频提炼：弹层按触发、信息量和打断程度选择；空间卡片按排布、遮挡、选中和归位说明。分类与证据见 [references/patterns.md](references/patterns.md)。键盘、数据提交与减少动画的验收项为本地工程补充，和原视频内容区分。

## 先选择承担任务的形式

- 一句话解释，无操作 → Tooltip。
- 锚定某个控件的较丰富说明或少量操作 → Popover。
- 在一组选项或动作中选择 → Dropdown；是菜单还是表单选择控件，要按语义再细分。
- 必须先作出决定才能继续 → Modal。
- 在原页面旁看详情或编辑 → Drawer；单独说明是否阻止背景操作，不能因叫 Drawer 就默认模态。
- 手机上的就近操作 → Bottom Sheet；明确拖动关闭与内容滚动的关系。
- 空间卡片先确定比较、浏览还是顺序叙述，再选纵深、扇形、圆柱、球面、螺旋或波浪网格。任务需要快速检索、密集比较时，普通列表/网格也可以更合适。

## 每份说明写清七项

1. **用户目标与场景**：使用者要完成什么，在哪个页面和设备上。
2. **触发**：点击、聚焦、悬停或明确事件；触摸设备有等价入口。
3. **初始和展开状态**：锚点、方向、占位、排布和遮挡；不要只说“高级、丝滑”。
4. **内容与操作**：具体字段、主次按钮、只读或编辑、前台与后台责任。
5. **背景和退出**：能否操作背景，关闭/取消/提交分别怎样；未保存内容不能被意外丢弃。
6. **选中与返回**：空间卡片从哪个位置来到前面，结束后回原位置、原层级、原次序；焦点回到可预期的控件。
7. **可观察验收**：至少覆盖一次正常流程、键盘/触摸替代、窄屏、减少动画、失败或取消。不要把未运行的验收列成通过。

## 输出格式

先给一句“选择的组件/排布及理由”，再给七项说明，最后给能直接用于实现的中文提示词和验收清单。缺失的产品决定可以标为假设；已有用户意图足够时直接起草，不反复确认常规细节。

对于已有可运行页面，先保留它的设计系统和交互约束，再将说明交给实际实现工具。没有运行环境时，完成标准是规格内部一致、可据此实现和验证，不是组件已经完成。

## 区分相邻任务

只挑颜色或排版不需要此 Skill；已确定组件、需要写代码时可把本说明作为现有前端能力的输入。安全性、登录和权限不能由动画决定。
