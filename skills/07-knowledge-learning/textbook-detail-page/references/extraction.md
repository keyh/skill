# 稿件体例要求与抽取规则

## 体例要求（工作任务式教材，高职）

每个项目一个 Word 文件，结构如下。方括号内为脚本识别的标记，必须单独成段、以【】包住：

```
项目三 高血压老年人照护                      ← 第一段 = 项目标题（脚本去掉“项目X”和“（N 学时）”）
【项目导读】
  正文若干段                                ← 第一段正文 = 项目简介
【学习目标】
  知识目标 / 一、知识目标                    ← 三个小标题；条目用 1. 2. 或 ① ② 编号
  1. …
  技能目标
  素质目标
任务1 评估高血压老年人的健康状况             ← “任务N 标题”，单独成段，< 40 字
【任务导入】                                ← 情境（问题图谱、任务样例取材）
【任务准备】
  一、知识准备                              ← 知识点：（一）（二）… 为一级，1. 2. … 为细目
  二、……（物品准备等，不抽）
【赛证直通】 对接《……》……                   ← 首段或标记同段的文字 = 赛证对接说明
【任务筹划】
【AI提问语】 / 【AI提示语】                  ← 首段 = AI 提问语
【任务实施】
  第一步 / 步骤一 ……                         ← 流程；其下 1. 2. … 为操作要点
【操作提示】
【任务检测】
【思政园地】                                ← 首段 = 思政园地摘要
【任务评价】
  表格：评价维度 | 评价标准 | 分值 | 自评 | 组评 | 师评    ← 技能点
【拓展训练】
……（下一任务）
【能力图谱】                                ← 项目末尾
  表格：能力层级 | 能力模块 | 能力点 | 学习场景 | 达成标准 | 实践要求
```

脚本靠这些标记切分，所以：
- 标记名写错（【赛政直通】）、多空格（【AI 提问语】）已在脚本里兼容；其它变体在 `extract_cap.py` 的 `SECTIONS` 和 `extract_book.py` 的 `TASK_FIELDS` 里增加。
- Word 自动编号（“一、”“（一）”“1.”）脚本能读；但手敲的编号和自动编号混用时，抽取结果里会出现重复编号，需要在稿件里统一。
- 评价表中“评价维度”列留空的续行归入上一维度；维度名中的分值“（35 分）”作为该维度总分。
- 单元格内的换行是条目分隔，原文中的斜杠（180/120 mmHg、缓释/控释）不是。

## 常见稿件问题与处理

| 现象 | 后果 | 处理 |
|---|---|---|
| 某任务没有【赛证直通】，或只有练习题没写对接对象 | 该任务赛证为空，对接率下降 | 补写一句对接说明（修订模式），并把任务加入 `pending.txt`，页面标“待作者确认” |
| 【项目导读】后第一段是编辑批注（如“总体字数太多”） | 项目简介显示批注 | 在 `book.meta.json` 的 `projectOverrides` 里指定 `intro` |
| 评价表分值合计 ≠ 100 | 页面按实际分值显示 | 如实显示，并在交付说明里列出请作者核对 |
| 任务标题出现在【任务实施】里（“任务1 …”作为步骤名） | 多抽出任务 | 脚本已忽略【任务实施】内的“任务N”；其它栏目内出现时在稿件里改成“步骤 N” |
| 项目文件是 .doc | 无法读取 | 用 Word / LibreOffice 另存为 .docx |
| 稿件带修订 | 抽到删除前的旧文 | 先 `accept_simple.py` 接受全部修订，用接受后的副本抽取 |

## 学科体例教材（本科，章 / 节）

没有任务实施、任务评价、知识准备时，五级能力结构抽不出来：

1. `assemble.py` 不传 `capability.json`；页面知识图谱、能力图谱、院校“图谱体系”显示“尚未导入”占位。
2. `extract_book.py` 的 `TASK_RE` 改为匹配“第N节 …”，`TASK_FIELDS` 按稿件的栏目改（如【案例导入】→ 问题图谱取材，【思政元素】→ sz）。
3. `terms` 改为 `{"unit1":"章","unit2":"节","unit2Full":"学习任务","abbr":"C","ring":"章"}`。
4. 学习目标常写在章首，抽取方式相同。

如果稿件有“知识点—技能点”对应（如每节末的“本节要点 / 技能训练”），可以仿照 `extract_cap.py` 写一个章节版抽取器，输出同样结构的 `cap.json`，后续步骤不变。

## 修订稿件的原则（当你需要改稿时）

- 用 Word 修订模式（`w:ins` / `w:del`）+ 批注，作者能逐条接受或拒绝；不要直接覆盖原文。
- 只改三类：错字 / 体例（栏目标记、编号）、体例统一（缺的栏目标记）、内容补写（赛证对接等）。补写的内容批注写明“待作者确认”，并列入 `pending.txt`。
- 生成一份修订清单（文件、位置、类型、原文、修改、理由）随稿件交回。
- 脚本：`scripts/revise_ms.py`（操作清单写在脚本的 `ops_for()` 里，按稿件改；需要 docx 工具目录 `DOCX_SCRIPTS`）与 `scripts/make_list.js`（修订日志 → 修订清单 .docx）。
