# 接入：详情页、学生端、教师端与可视化

## 与详情页 skill（textbook-detail-page）的关系

```
稿件 docx ─ 详情页 skill 抽取 ─▶ book.json（含 capability：项目—任务—流程—技能点—知识点）
                                      │
                                      ▼
                 本 skill：from_capability → 整理节点 + 先修关系 → validate → analyze
                                      │
                                      ▼
                         kg.json（先修图谱）+ 报告 + 审核表 + 图谱页面
```

- 能力图谱（五级结构）仍由详情页 skill 负责，本 skill 不改它；先修图谱是知识图谱的升级。
- 详情页 skill 里的 `related`（跨项目关键词关联）和 `support`（知识→技能）保持不变，作为 `hints` 参考；先修边经审核后，知识图谱栏目改为以先修边为主。
- 建议在 `book.json` 增加一个可选字段 `knowledgeGraph`，由 `kg.json` 精简而来（节点 id、名称、项目、类型、中心度、先修边与理由、状态）。详情页模板读到它时启用先修视图，读不到时退回现有的关键词网络。改模板前与用户确认。

## 用在哪些页面

| 位置 | 用法 | 依赖的字段 |
|---|---|---|
| 详情页 · 知识图谱 · 知识网络 | 先修关系网络：节点按项目分组，点选看先修 / 解锁；页面标“AI 预生成 · 待审核”的比例 | nodes、edges、status |
| 详情页 · 知识图谱 · 学习 / 教学路径 | 选一个目标知识点，按拓扑顺序列出前置知识；教师端显示“建议先复习” | edges（硬边为主）、anchors |
| 详情页 · 核心数据 / 重点难点 | 用中心度给“重点”提供依据，用先修闭包大小给“难点”提供依据 | centrality、unlocks、depth |
| 详情页 · 院校 · 内容质量 | 图谱体系自查：知识点数、先修关系数、已审核比例、覆盖率 | 统计 |
| 学生端工作台 · 接下来学什么 | 按学生已掌握的知识点算出“可学范围”（所有硬先修都已掌握的知识点，`analyze.py --frontier`），推荐时把边的理由说出来：“你已经会判断血压分级，所以可以学用药目标了” | edges（strength、reason）、学习记录 |
| 学生端工作台 · 卡在哪 | 答错某知识点的题时，沿硬边回溯，推荐回看最近的未掌握先修；生成个性化复习路径 | edges、evidence、assessmentPrompt |
| 学生端 AI 助手 | “先反问再给依据”：用 assessmentPrompt 反问，用 evidence 判断是否掌握 | assessmentPrompt、evidence |
| 教师端工作台 | 备课时提示本节课依赖的前置知识与常见断点；组卷时按知识点覆盖与层级出题 | edges、depth、standards |
| 首页 / 宣传 | 3D 图谱做“知识星河”式展示（只展示审核过的节点） | 全部 |
| AI 生成内容的校对 | AI 出的题、讲解、学习建议先映射到知识点，检查是否落在本书节点上、是否越过了学生还没学的先修、对接编号是否存在；不依赖模型“记得”教材内容 | nodes、edges、standards |

学习记录（哪些知识点已掌握）不放在 kg.json 里，由学生端按 `evidence` 判定后单独存储，只引用节点 `id`。所以节点 `id` 一旦上线不能改。

## 对接标准

- **1 号文五级结构**：知识点 → 技能点用 `standards` 里的 `skill:` 编号；需要时从技能点再上溯到流程、任务、项目。
- **岗课赛证**：证书或赛项模块用 `cert:`，名称与详情页 skill 的 `certs.json` 一致。
- **执业 / 等级考试大纲**：用 `exam:`，只存编号和条目名称，不复制大纲条文（大纲文本有版权）。
- **专业教学标准、课程标准**：用 `std:`。若要在页面展示标准原文，先确认该标准的发布方许可。

## 可视化选型

- **详情页、工作台**：用 2D、可读优先。分层有向图（按先修层或按项目分泳道）配列表视图；节点上直接显示名称；不要用 3D 当唯一入口。
- **首页、宣传、发布会**：可以用 3D（`assets/kg-viewer.html` 的思路），配合 web-motion-reference skill 里的“知识图谱”参考（如 3d-force-graph 的文字节点、连线流动光点）。
- **灵枢工程约束**（详见 web-motion-reference 的 `references/lingshu.md`）：three.js 按需加载、兼容 Chromium 64+（不支持 WebGL 2 时退回 2D 列表）、离屏与“减少动态效果”时停绘、像素比封顶、手机减量；不接第三方统计和翻译接口。
- 3d-force-graph 体积较大（压缩前约 1.4 MB，自带 three）。工程里已有 three 0.185 时，用 `3d-force-graph` 的 npm 包并共用工程的 three，或只用 d3-force-3d 自己画，避免重复打包。
