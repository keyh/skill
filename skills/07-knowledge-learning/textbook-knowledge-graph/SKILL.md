# 教材知识先修图谱

## 为什么要做

现在详情页的知识图谱只有“哪些知识点共用关键词”，回答不了三个关键问题：学这个之前要先会什么？哪些知识点最基础、最该讲透？学生卡住时该回到哪？先修图谱补上这一层。它和能力图谱分工明确：能力图谱按 1 号文的五级结构回答“学完能做什么”，先修图谱回答“按什么顺序学、缺了什么”。

图谱建好后可以直接支撑三件事：按已掌握的知识点算出“接下来能学什么”，推荐时说出理由，以及把 AI 生成的题目和讲解对回教材与标准。

方法来自 Marble 的开源课程图谱（见 `references/marble.md`），核心是三件事：
1. 把知识拆到**一个可教、可检测的想法**为止；
2. 每个想法写**可观察的达标证据**和**一个检测问题**；
3. 只连**直接先修**，每条边标**硬 / 软**并写一句**理由**，整张图必须无环。

## 产出

一个 `kg.json`（格式见 `references/schema.md`），加上按需生成的：分析报告、学习路径、编辑审核表（CSV）、3D 交互图谱页面。所有模型生成的内容都标 `status: "ai"`，页面显示“AI 预生成 · 待审核”，编辑审核后改为 `reviewed`，作者确认后改为 `confirmed`。

## 流程

脚本在 `scripts/` 下，只用 Python 标准库。Claude Code 中写成 `${CLAUDE_SKILL_DIR}/scripts/…`，其他环境在 skill 目录下运行。

### 1. 取原料
- 已经用详情页 skill（textbook-detail-page）抽取过的教材，直接用它的 `book.json`（或 `capability.json`）：
  ```bash
  python3 scripts/from_capability.py book.json -o kg.json            # 整本
  python3 scripts/from_capability.py book.json -o kg.json --units 1-4  # 先做几个项目
  ```
  每个【任务准备】知识点生成一个候选节点，带出处 `anchors`、细目 `sub`、所在任务的技能点与流程 `context`，原来的关键词关联放在 `hints` 里作参考。
- 没有 `book.json` 时，按 `references/schema.md` 手工搭骨架：节点只需 `id / name / unit / anchors`。

### 2. 整理节点（拆、并、补）
读 `references/authoring.md` 的“节点”一节，逐个项目处理：
- **合并**跨项目反复出现的通用知识（如“健康教育的原则”），变成一个基础节点；各病种里的具体应用保留为独立节点，再用先修边连到基础节点。
- **拆分**一个节点里装了好几件事的（描述写不进两句话、证据超过 4 条）。
- **补写**每个节点的 `type`、`description`、`evidence`（2–4 条）、`assessmentPrompt`、`standards`（对接的技能点、赛证条目）。
- 内容必须能在稿件里找到依据，不要凭常识补知识点。

### 3. 建先修关系
读 `references/authoring.md` 的“先修关系”一节：
- 每个节点找 0–4 个**直接**先修；能通过别的先修间接到达的不要连。
- `hard` = 不会它就学不了；`soft` = 有它学得更好。拿不准时用 `soft`。
- 理由写成一句可核对的话：“要先能判断血压分级，才能确定监测频率”。
- 先做项目内，再做跨项目（跨项目的先修最有价值，也最容易出错）。
- 整本书较大时按项目分批，最后单独做一轮跨项目连接与去重。

### 4. 校验
```bash
python3 scripts/validate.py kg.json --book book.json
```
检查：字段与取值、引用完整、**有无循环**、冗余边、孤立节点、**先修出现在更靠后的项目**（方向可能反了，或教材该在前面补提示），以及原知识点的覆盖率。错误必须修完；警告逐条处理或在交付说明里解释。冗余边可以用 `--fix-redundant` 自动删除（按强度判断：硬边只有存在全硬的替代路径时才删）。

整本书分批做完、合并之后，再做一轮全书整理：同一通用内容在多个项目重复讲（转介衔接、用药依从性、生活方式干预等）时**不跨项目合并节点**，用软边把后者连到第一次讲的地方，并记进 `editorial.repeats`；“先用后讲”记进 `editorial.forwardUse`。这两类会写进报告的“编辑提示”。

### 5. 分析与导出
```bash
python3 scripts/analyze.py kg.json --write                 # 写回 centrality / depth / unlocks
python3 scripts/analyze.py kg.json --report 图谱分析.md    # 重点、难点、桥梁知识点、各项目概况、编排顺序提示
python3 scripts/analyze.py kg.json --path kp_p03_101       # 学会某个知识点的完整学习路径
python3 scripts/analyze.py kg.json --frontier kp_p01_101 kp_p03_101   # 已掌握这些，现在可以学什么（带理由）
python3 scripts/analyze.py kg.json --review 审核表.csv     # 给编辑的审核表（Excel 可打开）
python3 scripts/analyze.py kg.json --viewer 图谱.html      # 3D 交互图谱（点选看先修 / 解锁链与学习路径）
```
**计算口径**：软边的意思是“先学会更顺”，不能一路传递——全书试跑时，软边串起来形成了 25 层的“链”，让综合性知识点看起来要先学 127 个知识点。所以层级、先修数量、难点、学习路径和图谱页面里的先修 / 解锁链只沿硬边追溯；软先修只看直接一层，作为“建议先看”；中心度把软边按 0.4 的权重计入。硬边稀疏时“现在可以学”的范围会很大，`--frontier` 会按软先修的掌握情况和教材顺序排出推荐顺序。

### 6. 交付
- 给用户：`kg.json`、分析报告、审核表；需要演示时给图谱页面（适合发布为 artifact）。
- 在回复里用几句话说清：节点和边的数量、硬 / 软比例、最重要的 3 个发现（如“生命体征测量是 9 个项目的共同先修”）、还剩哪些警告、哪些需要编辑或作者确认。
- 接入详情页、学生端、教师端的方式见 `references/integration.md`；可视化做成正式页面时，同时用 web-motion-reference skill 查参考并遵守灵枢的工程约束。

## 规则
- **依据稿件**：节点与关系都要能在稿件里找到出处（`anchors`）；纯常识性补充标在 `notes` 里，并保持 `status: "ai"`。
- **只连直接先修，保持无环**：图要能拓扑排序，才能生成学习路径。
- **人审在环**：AI 预生成的关系不能直接当结论展示；页面上要标状态，统计数字只算已审核的部分时要写明。
- **对接标准只存编号**：执业资格考试大纲、职业技能等级标准等第三方文本有版权，`standards` 里只放编号和名称，不复制条文（Marble 也是这样处理受限来源的）。
- **不要直接搬 Marble 的数据**：那是美英小学课程，学科不对口；而且派生数据库须按 ODbL 开源。我们借的是方法和字段设计，数据是自己的。
- **可视化不外发数据**：不要接第三方统计脚本或免费翻译接口（zhulin025 的演示页两者都有），教材内容不能发到外部服务。
